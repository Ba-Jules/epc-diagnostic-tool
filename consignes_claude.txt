CONTEXTE

Mouhamed BA a compris que "Référence" est un libellé métier court de l'indicateur, indépendant de son ordre.

Il précise maintenant son besoin :

1. la Référence doit être courte ;
2. idéalement 3 à 4 mots ;
3. elle doit synthétiser l'indicateur avec concision, clarté, précision et pertinence ;
4. elle doit être générée automatiquement lors de la création/modification d'un indicateur ;
5. elle doit servir de libellé sous les histogrammes, en abscisse ;
6. l'utilisateur doit pouvoir la corriger si nécessaire.

==================================================
2. GÉNÉRATION AUTOMATIQUE DE LA RÉFÉRENCE
==================================================

Lors de la création d'un indicateur :

l'utilisateur saisit d'abord son énoncé.

À partir de cet énoncé, proposer automatiquement une Référence courte.

Cible :
3 à 4 mots de préférence.

Qualités attendues :
- concise ;
- claire ;
- précise ;
- pertinente ;
- compréhensible hors contexte ;
- représentative de l'idée principale ;
- sans formulation inutile du type "Nous avons", "Il existe", etc.

Exemple :

Indicateur :
"Nous offrons régulièrement la formation au personnel"

Référence possible :
"Formation du personnel"

IMPORTANT :
la Référence générée reste MODIFIABLE par l'utilisateur avant enregistrement.

==================================================
3. NE PAS RENDRE L'OUTIL DÉPENDANT DE L'IA
==================================================

La création/modification d'un indicateur doit continuer à fonctionner :
- sans connexion à un service IA ;
- si l'IA est indisponible ;
- si aucune clé/API n'est configurée.

Examiner l'infrastructure IA déjà présente dans :8810.

Si une fonction IA existante permet proprement de proposer cette synthèse, elle peut être utilisée comme amélioration facultative.

Mais prévoir obligatoirement un fallback local/déterministe permettant de proposer une référence courte sans appel IA.

Ne crée pas une nouvelle dépendance externe uniquement pour cette fonction.

==================================================
4. COMPORTEMENT DE L'INTERFACE
==================================================

Flux souhaité :

Énoncé de l'indicateur
→ Référence proposée automatiquement
→ utilisateur peut conserver ou modifier
→ Enregistrer.

La Référence doit rester visible dans le formulaire.

Prévoir un petit bouton/action du type :

"Regénérer"

ou équivalent sobre, permettant de refaire une proposition à partir de l'énoncé courant.

Ne pas écraser silencieusement une Référence que l'utilisateur a volontairement modifiée.

Si l'utilisateur modifie ensuite l'énoncé :
- ne pas remplacer automatiquement une Référence personnalisée sans son accord ;
- permettre de demander explicitement une nouvelle proposition.

==================================================
5. UNICITÉ
==================================================

Conserver la règle ajoutée précédemment :

deux indicateurs d'un même domaine ne peuvent pas avoir exactement la même Référence.

Lors de la génération automatique :
- vérifier l'unicité dans le domaine ;
- si la proposition existe déjà, produire si possible une variante pertinente ;
- sinon demander à l'utilisateur de la différencier.

Ne jamais ajouter artificiellement un numéro incompréhensible uniquement pour contourner le contrôle.

==================================================
6. LONGUEUR
==================================================

3 à 4 mots = cible ergonomique, pas règle destructrice absolue.

Ne tronque jamais brutalement une Référence existante.

Pour les nouvelles propositions automatiques :
viser 3–4 mots.

Si 5 mots sont exceptionnellement nécessaires pour préserver le sens, préférer une référence claire à une règle mécanique.

C'est un point explicitement demandé par Mouhamed BA.

Pour TOUS les histogrammes/graphiques où les indicateurs apparaissent en abscisse :

afficher la Référence courte.

Exemple :

Vérifier également :
- lisibilité avec plusieurs indicateurs ;
- absence de chevauchement excessif ;
- cohérence après changement de domaine ;
- cohérence standardisé/gradué.
